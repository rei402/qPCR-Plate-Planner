# qPCR Plate Planner · v2.1.2 冻结版

**qPCR 孔板设计、Mix 计算与加样助手**。这是一个完全静态的中文网页工具，面向 singleplex qPCR / RT-qPCR 的实验准备。它帮助规划 96 / 384 孔板、分别计算各 assay 的 Master Mix、逐步高亮加样孔，并生成 A4 横向或纵向操作单。它不分析 Ct 或扩增曲线。

## v2.1.1 默认设置

新页面及 `newProject()` 默认采用实验室优先布局（首位选项）、A4 纵向和鲜明科研配色。升级时旧本机缓存的排板模式与打印方向不会覆盖这组新默认值；其它偏好保留。升级后手动选择的模式、方向和配色继续记忆。打开已有项目、恢复草稿或加载历史示例时，使用其保存的设置与原孔位，不强制替换。旧格式缺省字段继续按原有兼容规则恢复。

## v2.1 实验室优先布局

默认使用「实验室优先布局（内参固定 + 剩余空间紧凑填充）」。首次普通实验 **QC / Controls、NTC、阳性及 No-RT 均关闭**。启用 QC 只展开配置，不自动添加对照；“加载示例”仍载入原有 NTC 示例，用于演示及旧版兼容。

- 一个内参自动作为主内参；多个内参须明确选择，其余内参按输入顺序排为普通 assay。没有内参时不预留行。
- 标准区将主内参放在 96 的 A/H 行。每个样品占宽度为 R 的连续列组，普通 assay 每行一个、按用户顺序排布。超过 8 个 assay 时先排主内参和前 7 个普通 assay，其余作为待排组。
- 384 按 Q1=A1–H12、Q2=A13–H24、Q3=I1–P12、Q4=I13–P24 理解；先依次尝试全部标准列组。top 使用 A/I，bottom 使用 H/P。
- 之后从上到下、从左到右找剩余空间：优先放高为剩余所选 assay 数、宽为 R 的样品矩形，主内参在矩形首行/末行；放不下时寻找连续水平重复条带，仍放不下才开下一板。矩形和条带均不跨 384 分区。
- 每个 Sample × assay 的技术重复始终完整、连续、同板；不同 assay 必要时可分板，不额外复制内参。每个实际待用孔都检查保留状态，不因未使用行的保留孔阻挡整个标准列组。
- 对照使用剩余空间，优先完整列组；逐板对照和校准会预先模拟可行性，避免样品挤占必需对照。跨板校准首板使用完整常规重复组，后续每个 assay 一个校准孔。
- 容量预检查直接运行同一排板模拟，显示标准/剩余样品及孔数、总对照、实际板数与使用率。跨区或多 assay 样品可分别计入两区人数，不应把两者直接相加当总样品数。
- 关闭已有 QC 需点击“关闭并重新计算”，移除 NTC、阳性、No-RT、校准并重新生成结果。取消保留原结果。旧 JSON 缺少 QC 字段时按实际控制设置推断，已有 NTC 不会消失。
- 保存 JSON 包含 layoutMode、referenceRowPreference、primaryReferenceGeneId 与实际孔位/区域类别。恢复保留原坐标；修改布局须明确重新生成。旧项目仍使用保存的旧模式。
- 实验室优先布局采用顺序填充；高级设置的平衡分板仅用于旧模式。此模式支持 R=1–12，连续对照重复也不能超过分区 12 列；旧模式继续支持原有范围。启发式排布不保证数学全局最少板数。

详细实现和验收结果见 `LAB-LAYOUT-REPORT.md`；自动测试证据见 `TEST-REPORT.md`。

## 直接使用

1. 完整解压工具文件夹，Windows 双击带软件图标的 **`qPCR Plate Planner.exe`**。它通过默认浏览器打开同目录的网页，移动整个文件夹后仍可用。也可运行 `创建工具快捷方式.cmd`，生成指向启动程序的快捷方式；文件夹移动后重新创建快捷方式。其他系统直接打开 `qPCR Plate Planner.html`。首次进入可点击“加载示例”，快速查看完整流程。
2. 每行输入一个 Sample、Target gene 和可选的 Reference gene。也可从 Excel 复制一列或多列、直接粘贴到文本框；制表符和空行会自动分隔。**重复名称会报错，不会自动改名。**
3. 选择孔板、技术重复、对照，并核对反应体系。`Template` 单独识别，不计入 Master Mix。
4. 点击“生成孔板与加样方案”。右侧查看 SVG 孔板、逐基因 Mix、逐步加样及检查单。
5. 在“打印 / 导出”中切换 A4 横向或纵向，预览立即更新；可打印当前板或全部孔板。也可导出全部孔板的 UTF-8 BOM CSV、保存/打开项目 JSON。

Windows 中 HTML 文件显示 Chrome 图标，是其默认打开方式决定的；新版 EXE 已内嵌软件图标，不需要修改系统文件关联。网页仍在默认浏览器中运行，浏览器任务栏图标由浏览器管理。请保留启动程序旁的网页、脚本、样式与图标文件。

设计输入停止 300 ms 后更新容量预检，修改设计后旧排板立即失效；主动生成会取消待执行预检。默认检查单中的“NTC 已最后加入”按本板实际孔位判断：没有 NTC 的板标注“不适用”并禁用勾选，打印同步标注。

### 批量编辑保留孔

点击孔板右上角的“编辑孔板”。编辑模式中，单击孔位或行列标题会选择相应范围；Ctrl/Cmd + 单击可多选，Shift + 单击选择同类锚点到目标的连续区域，拖动孔位可框选矩形。▲ A1 选择全部孔。工具栏可选择全部、选择已保留、反选、清除选择，并将所选孔批量“设为保留”或“恢复可用”。撤销/重做只记录真实的保留孔修改，最多 50 步；编辑模式下还可使用 Ctrl/Cmd+A、Esc、Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z / Ctrl/Cmd+Y。输入框获得焦点时这些快捷键不会拦截文本编辑。

选择是临时状态，不进入 JSON、CSV、打印或排板计算。保留孔设置对所有板生效；修改后原排板立即失效，须点击“重新生成孔板”核对新布局和 Mix。如果选中的孔已经分配反应，设为保留前会先确认。完成编辑会清空临时选择。

### 平板加样辅助

生成孔板后，打开“逐步加样”页，选择对应 Plate，点击“打开平板加样辅助”。建议先进入全屏，再将透明孔板放在屏幕中央，确认 A1 方向；通过单指拖动、双指缩放/轻微旋转或右侧按钮，使四角及中央孔位与实体孔板重合。检查后点击“锁定位置并开始”。此后孔板区域的触摸不会移动光点，屏幕只点亮现有加样步骤中的孔位；没有孔位的配制、封板等步骤保持全暗。

控制区位于孔板投光区域之外，提供上一步、下一步、暂停、一键熄灭、亮度和颜色选择。校准可按 96 / 384 孔分别保存到**此设备的 LocalStorage**，再次进入时由用户选择是否使用，并仍需核对后锁定。屏幕方向、可用显示区域或全屏状态变化时，已锁定的投光会暂停并熄灭，须重新校准。浏览器不支持全屏或 Wake Lock 时仍可使用；请自行检查系统自动锁屏设置。设备校准、亮度和投光颜色仅保存在此设备；执行步骤完成时间及实验显示偏好随项目 JSON 保存。重新校准不会清空执行进度。

屏幕发光仅用于孔位定位；光敏试剂应遵循厂家避光要求。孔板外表面保持清洁干燥，避免按压、划伤屏幕或让已加反应液的孔板长时间处于发热屏幕上。本功能不能代替实验人员最终核对。

打开 `tests.html` 可在浏览器运行核心计算测试。开发机若有 Node.js，也可在项目目录运行 `node tests.js`；**最终使用者无需 Node.js、Python、服务器或安装依赖。**

## v2 新功能使用

### 草稿与继续执行

输入更改后约 250 ms 自动保存本机草稿。重新打开时先选择恢复或丢弃旧草稿；处理此提示前不会覆盖旧草稿，也暂不保存新草稿。生成后的草稿含原孔位与执行记录；尚未生成的草稿只恢复表单。改变反应设计会隐藏旧结果并清空旧进度。元信息、配色、缩放、打印方向和检查单变化保留排板及进度。

“完成并进入下一步”记录该步完成时间；返回上一步仅浏览，需点击“将本步标为待执行”才能重开。最后一步完成后不自动循环。“继续未完成步骤”定位当前板第一项未完成步骤。平板辅助共享同一进度。导出 JSON 后状态标为已导出；后续更改会再次提示。关闭页面的提示由浏览器控制，本机草稿不能替代导出的实验记录。

打开项目默认选择“恢复保存的排板”，先检查格式、反应完整性、保留孔及逐板对照/校准覆盖，再恢复原坐标并重新计算 Mix。失败时保留当前项目。“按当前版本重新排板”使用输入重新计算，清空旧执行进度。旧校准文件若覆盖不完整，必须由用户明确选择重新排板；不自动修正原孔位。

### 样本表和检测矩阵

展开样本表，粘贴 Excel 的表头和数据，或选择 CSV / TSV 文件。必须包含 `Sample` / `样本` 列；可选 `Group` / `组别`、`BiologicalReplicate` / `生物重复`。样本名不允许空值、重复、换行和制表符；名称可含逗号。示例见 `examples/sample-table.tsv`。组别和生物重复可继续编辑，保存到 JSON，并输出到布局 CSV 与打印图例。

默认检测所有样本与 assay；勾选稀疏矩阵后按格子选择，需要至少一个 Target / Sample 组合。全不选时阻止生成。未被任何样本选择的 assay 不产生反应或对照。跨板校准开启后，所选校准样本会在所有板覆盖全部有效 assay。

### 对照与独立配方

选择项目或逐板对照范围。逐板 NTC / 阳性覆盖本板使用的 assay；逐板 No-RT 覆盖本板出现的所选样本 × assay。重复数分别配置，容量预检含逐板对照和校准新增孔。

展开“每 assay 独立配方”，选择 assay，编辑组分、体积、预混及余量后点击“应用”。编辑未应用的内容不会改变已生成方案。恢复通用配方可移除该 override。每个 assay 的总反应体积必须与组分合计一致；独立预混不能包含 Template 或通用 Mix。

### 试剂汇总与多通道

Mix 页的“全板试剂汇总”合并同名同角色通用试剂；引物和探针保持 assay 区分。配制量含最终 Mix 与预混各自余量；实际用量按真实孔数计算；余量是二者之差。Template、NTC 替代水、No-RT、阳性及跨板校准材料按实际孔数单列，不额外预配。预混 transfer 不重复计为原料，另列配制/转移表。可导出 CSV 或分页打印。

多通道按当前步骤中相同材料和体积的连续孔位生成完整批次；384 孔可选择相邻或 8/12 通道隔孔步距。缺孔和剩余孔作为单通道补加。软件不推断设备型号的孔距兼容性；选定步距前需确认设备与孔板。单通道、工作站及其他设备保留孔位清单。

## 离线与部署

- **本地文件**：复制整个文件夹，在另一台电脑双击 `qPCR Plate Planner.html` 即可使用核心功能。`file://` 模式下浏览器通常不允许 Service Worker，因此不会提供 PWA 安装或缓存，但排板、保存、导出和打印仍可用。
- **静态托管**：将整个文件夹原样上传到 GitHub Pages、Netlify、Cloudflare Pages 或实验室网站。需要 HTTPS（或浏览器认可的 localhost）才可注册 Service Worker。首次加载并缓存后可离线打开；新版本有可用更新提示，由用户主动应用后保存草稿、切换缓存并刷新；执行中不会自动刷新。入口 URL 为 `qPCR%20Plate%20Planner.html`，静态托管需使用此完整地址。
- 无后端、数据库、远程字体、分析脚本或 API。样本名和实验设置不会上传。LocalStorage 保存通用设置、检查单、手动配方预设及完整项目草稿。共享电脑上可在恢复提示处丢弃草稿；清除浏览器站点数据会删除草稿与设备偏好。请导出 JSON 作为可迁移的实验记录。存储禁用或容量不足时，状态栏显示草稿尚未保存，JSON 导出仍可使用。

## 功能与计算规则

- **反应数**：默认每个 Sample × assay × 技术重复；稀疏检测矩阵只生成所选组合。项目范围对照每个有效 assay 加入一次设定数量的 NTC / 阳性；逐板对照按各板实际 assay 加入，No-RT 按各板出现的所选样本 × assay 加入。旧模式跨板校准在首板固定一个常规校准样本反应；实验室优先模式保持该样本完整技术重复组。矩阵缺少该组合时补一个校准反应。后续板每个有效 assay 增加一个校准孔。生成后逐项校验预期与实际数量。
- **Master Mix**：每个 assay、每块孔板单独计算。`N_prepare = max(ceil(N_required × (1 + waste%)), N_required + minimumExtra)`。每个非 Template 组分的用量为单反应体积 × `N_prepare`。引物、探针名称自动加 assay 前缀；不同基因不合并。
- **独立 Primer / Assay Mix**：默认关闭。启用后由用户勾选原配方中的引物、探针、水或其他组分；软件按 assay 分别预混，Final Master Mix 中用一项独立 Mix 替换所选组分。Template 与通用 Mix 不能被选入。独立 Mix 配制量先满足 Final Master Mix 的配制份数，再按当前损耗比例和最低额外份数增加自身余量；独立 assay 配方编辑器可为预混设置独立余量；空值继承通用参数。
- **低体积**：逐孔加的 Template 低于阈值时显著警告。独立 Mix 关闭时，旧版小体积组分提示保持不变；启用后按每块板、每个 assay 的实际批量吸取总体积检查被选组分。阈值由用户设置，不能代替移液器规格检查。
- **保留孔**：支持 `A1`、`H10-H12` 等范围，也可在孔板编辑模式批量选择与应用。每块板相同坐标都会保留；更改后须明确重新生成排板。
- **旧模式多板**：顺序填充优先保持一个 Sample/assay 的技术重复在同一板；平衡分板按反应组分配到负载较小的板。容量不足时必要情况下可拆开一组反应，最终应按每块板的 CSV 和孔位复核。
- **逐步加样**：启用独立 Mix 时，先依次配制各 assay 的独立 Mix 和 Final Master Mix；随后按 assay 分液，再按 Sample 加 Template，接着添加 No-RT、阳性/校准，NTC 最后加入。最后给出封板、离心、检查与上机提示。当前分液步骤对应孔在 SVG 上高亮。

## 排板算法

实验室优先策略见 `lab-layout.js` 与上方规则。以下是三个旧模式的算法，继续保持：核心见 `core.js`。先生成带唯一 ID 的反应组，再根据模式按 gene 或 Sample 排序；按可用孔容量分板后，针对每块板构造横向、纵向、蛇形、区块四种确定性候选。评分综合同 assay 相邻、同 Sample 相邻、技术重复相邻、占用矩形紧凑度，以及所选多通道在实际孔位中可完整覆盖的批次。选择最高分候选；同分时保持固定候选顺序。保留孔在候选坐标生成前排除。算法是可解释的启发式，不承诺数学全局最优，也不推断实际移液器与 384 孔板的孔距兼容性。

每次生成后检查：所有反应恰好分配一次、每块板每孔最多一反应、没有进入保留孔、总反应数和各类型对照数正确、逐 assay Mix 反应数与孔板一致。失败时不显示看似正常的孔板。

启用独立 Mix 时还逐组分检查：原配方中的每个非 Template 组分恰好出现在独立 Mix 或 Final Master Mix 的直接组分之一，不能重复；独立 Mix 的转移体积等于其单反应体积乘以 Final Master Mix 配制份数；最终每反应化学组成及总体积与原配方一致。

## 打印与导出

打印使用 `print.css` 和动态 `@page` 规则，新页面默认 A4 纵向，亦可选横向；载入旧项目时保持该项目的打印方向。横向的 96 孔采用板图与 Mix 左右布局；384 孔让板图先占满纸宽。纵向采用独立的单栏流程：板图、图例、Mix、检查单和备注依次排列。多板“打印全部”按板分页；板图避免跨页截断。样本或 assay 特别多时，详细信息可流到第二页，不会为强行塞进一页而无限缩小字体。384 孔图例采用多栏 `Sxx/Txx` 映射。CSV 包含 Plate、Well、Row、Column、Sample、SampleCode、Target、TargetCode、GeneType、ReactionType、TechnicalReplicate，并追加 ReactionId、SampleId、AssayId、Group、BiologicalReplicate 和 ReactionVolume_uL，采用 UTF-8 BOM 便于中文 Excel 打开。

## 已知边界

- 当前版本面向 **singleplex**；不做 multiplex 染料兼容、Ct / ΔCt 分析或自动引物设计。
- 默认使用通用配方，可为每个 assay 应用独立配方、反应体积和预混设置；每套配方均独立校验，步骤、Mix、CSV 和打印使用相应体积。
- 384 孔屏幕版使用更宽的孔位、独立的双行字号与垂直偏移、最小板图宽度及水平滚动；可将屏幕板图放大到 125% 或 150%。打印版另设字号，名称使用稳定的 `Sxx` / `Txx` 编号和多栏图例；打印前务必核对长名称映射。
- No-RT、阳性默认各 1 孔，可分别配置 1–24 个技术重复。生物重复字段仅记录样本身份，不会复制反应。
- 冻结版上限为 500 个样本、100 个 assay、20000 个总反应（含对照）；超限须拆分项目。颜色和边框样式仅辅助辨认，仍应核对 Sxx / Txx 图例及完整名称。
- PWA 安装依赖浏览器与静态站点环境；`file://` 打开不注册 Service Worker。

## 冻结与复核

冻结版本：**2.1.2 / 2026-10-02**。项目 JSON schema 仍为 1，软件版本 2.1.2、布局版本 3。发布 ZIP 与其 `.sha256.txt` 位于 `releases/`；发布采用显式文件清单，不包含私人实验 JSON、浏览器草稿、`.Rhistory` 或 `node_modules`。发布包完整解压即可运行。

开发复核环境为 Node.js 24。在项目目录执行：

```powershell
npm ci
npm test
npm run verify
```

`npm run release` 在 Windows 上使用系统 .NET Framework 编译器重建带图标的启动程序，再执行全部测试，通过后生成测试报告、逐文件 SHA-256 清单与 ZIP。最终使用者无需编译；单独重建启动程序可运行 `npm run build:launcher`。`FREEZE-MANIFEST.json` 本身不递归计算自己的哈希，ZIP 的外部校验值覆盖它。校验清单覆盖发布文件，额外创建的快捷方式和实验项目不参与冻结校验。冻结后需要修改时，请新建版本、更新版本文件和缓存版本、重新测试及打包。

PWA 更新在发送激活请求之前、切换完成刷新之前，各保存一次草稿。旧草稿待处理或保存失败会阻止操作并保留页面；恢复存储后可重新点击更新。另一标签页的更新不会自动刷新当前实验。实机验收记录见 `DEVICE-CHECKLIST.md`。

自动化覆盖核心算法、旧示例恢复、全部新功能、DOM 事件、原孔位保存/打开、打印内容和依赖完整性；测试明细见 `TEST-REPORT.md`。本次没有真实浏览器视觉截图、实体屏幕校准或打印机分页实测。实际用于实验前，请在使用设备上复核：96/384 孔 A1 和四角对齐；长名称与独立配方的打印/PDF分页；触控框选；全屏、旋转后的重新校准；PWA 更新提示。DOM 测试中的设备尺寸为模拟值。
